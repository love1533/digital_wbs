# WBS 관리 스킬

`wbs_data.json` 단일 파일로 WBS 전체 데이터를 관리한다. 파일 수를 최소화하는 것이 핵심 원칙이다.

## 데이터 파일 위치

- **메인 데이터:** `wbs_data.json` (프로젝트 루트)
- **백업:** `wbs_data.backup.json` (JSON 파싱 실패 시에만 생성)
- 태스크별, 날짜별 별도 파일을 절대 만들지 않는다

## 작업 유형별 처리

### 1. WBS 초기 생성

사용자가 프로젝트 정보(이름, 기간, 페이즈, 태스크 목록)를 제공하면:
1. `wbs_data.json` 존재 여부 확인
2. 없으면 새로 생성, 있으면 사용자에게 덮어쓰기 확인
3. 페이즈 약어 규칙: 분석→AN, 설계→DS, 개발→DV, 테스트→TS, 이행→DP, 운영→OP
4. 태스크 ID 자동 부여: `{페이즈약어}-{3자리순번}` (예: AN-001)

### 2. 태스크 추가/수정/삭제

- **추가:** 해당 페이즈의 마지막 순번+1로 ID 자동 부여
- **수정:** ID로 태스크를 찾아 요청된 필드만 변경
- **삭제:** ID로 태스크를 찾아 제거 (삭제 전 확인)

### 3. 일별 실적 기록

가장 빈번한 작업이다. 효율적으로 처리해야 한다.

**단건 입력:**
```
"AN-001 오늘 30% 진행, 인터뷰 3건 완료"
→ AN-001의 daily_log에 {date: "2026-04-10", percent: 30, note: "인터뷰 3건 완료"} 추가
```

**일괄 입력:**
사용자가 여러 태스크의 실적을 한번에 입력할 수 있다:
```
"오늘 실적:
AN-001: 30%, 인터뷰 완료
AN-002: 50%, 문서 작성중
DS-001: 10%, 킥오프 완료"
```

**처리 규칙:**
- 날짜를 명시하지 않으면 오늘 날짜(2026-04-10 기준) 사용
- 같은 날짜에 이미 기록이 있으면 덮어쓰기
- 퍼센트가 100이면 status를 `완료`로 자동 변경
- 이전 기록 대비 진척률이 감소하면 사용자에게 확인

### 4. 상태 변경

status를 직접 변경한다: `대기`, `진행중`, `완료`, `지연`, `보류`

### 5. 일괄 작업

페이즈 전체, 카테고리 전체 등 범위 지정 변경을 지원한다.

## JSON 읽기/쓰기 패턴

```python
# 항상 이 패턴으로 읽고 쓴다
import json

# 읽기
with open("wbs_data.json", "r", encoding="utf-8") as f:
    data = json.load(f)

# 수정 후 쓰기 (들여쓰기 2, 한글 유지)
with open("wbs_data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

## 유효성 검증

모든 쓰기 작업 후:
- JSON이 유효한지 파싱 테스트
- 필수 필드 존재 확인 (id, phase, name, start_date, end_date)
- percent 범위 (0~100)
- 날짜 형식 (YYYY-MM-DD)
